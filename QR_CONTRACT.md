# QR_CONTRACT.md — контракт QR-кода для 1С

Этот документ описывает, каким должен быть QR-код, который печатает 1С на производственной накладной, чтобы приложение «Контроль металла» могло его правильно прочитать. Документ рассчитан на программиста 1С, не требует знания веб-разработки.

## Что должен содержать QR-код

QR-код должен кодировать обычную интернет-ссылку (URL) следующего вида:

```
https://kontrol-metalla.example.ru/check?ral=7024&thickness=0.50&manufacturer=uzbekistan&coating=viking
```

(Реальный домен будет сообщён отдельно после деплоя — здесь используется как пример.)

Ссылка состоит из адреса `.../check` и четырёх параметров после знака `?`, разделённых `&`. Порядок параметров не важен. Все четыре параметра — **обязательны**, ни один нельзя пропустить.

## Параметры

### `ral` — цвет по каталогу RAL

- Формат: только цифры, без слова «RAL», без пробелов.
- Пример: `ral=7024` (не `ral=RAL7024`, не `ral=RAL 7024`).

### `thickness` — толщина металла в миллиметрах

- Формат: число с точкой в качестве разделителя (не запятая), например `0.50` или `0.5`.
- Пример: `thickness=0.50`.
- Приложение само приводит `0.5`, `0.50`, `0,50` к одному и тому же значению — но **точка предпочтительна**, запятая в URL требует дополнительного кодирования (`%2C`) и может привести к ошибкам при копировании, поэтому используйте точку.

### `manufacturer` — производитель металла

- Формат: код производителя **строчными латинскими буквами**, без пробелов.
- Список допустимых кодов и их точное написание фиксируется в справочнике приложения (администратор «Контроль металла» его ведёт) — актуальный список нужно запросить у администратора приложения перед настройкой выгрузки из 1С, он может меняться.
- Пример: `manufacturer=uzbekistan`.
- Если 1С использует другое написание того же производителя (например, `Uzbekistan_Metal`) — администратор приложения может зарегистрировать это написание как допустимый вариант (alias). Без регистрации такое написание будет считаться неизвестным и даст ошибку у работника — **лучше согласовать точные коды заранее, чем чинить постфактум**.

### `coating` — покрытие

- Аналогично `manufacturer`: код строчными латинскими буквами, точный список — у администратора приложения.
- Пример: `coating=viking`.

## Что произойдёт, если значение не распознано

Приложение **никогда не пытается угадать или исправить** значение. Если хотя бы один параметр:

- отсутствует в ссылке (пустой);
- имеет формат, который не удаётся разобрать (например, буквы в `ral`);
- не совпадает ни с одним известным приложению значением (для `manufacturer`/`coating` — ни с кодом, ни с зарегистрированным вариантом написания);
- совпадает с известным значением, но эта запись деактивирована администратором приложения (например, производитель, с которым больше не работают);

— работник увидит на экране сообщение **«ОШИБКА В НАКЛАДНОЙ»** с отдельной строкой на каждое нераспознанное поле (например: «Неизвестное значение поля «покрытие»: rooftop_barhat» или «Значение поля «производитель» деактивировано: severstal»), и не сможет продолжить проверку рулона. Если ошибок несколько сразу — показываются все, не только первая. Это сделано намеренно: лучше остановить работника с понятной ошибкой, чем позволить проверку с неверными данными.

**Вывод для 1С:** значения `manufacturer` и `coating`, которые печатаются в QR, должны точно (посимвольно) совпадать с кодами, зарегистрированными в приложении. Любое расхождение = работник не сможет продолжить, пока кто-то не поправит либо накладную, либо справочник.

## Что НЕ нужно включать в QR

- Номер заказа, номер накладной, дату, клиента, партию, вес, площадь — приложение это не использует и не хранит.
- Разделители в `thickness` в виде запятой — используйте точку.
- Слово «RAL» в параметре `ral` — только цифры.

## Пример полной ссылки

Требуется рулон: RAL 7024, толщина 0,50 мм, производитель Узбекистан (код `uzbekistan`), покрытие Viking (код `viking`):

```
https://kontrol-metalla.example.ru/check?ral=7024&thickness=0.50&manufacturer=uzbekistan&coating=viking
```

QR-код должен закодировать именно эту строку целиком (как обычный URL для веб-браузера — 1С не обращается ни к какому API, только печатает QR).

## Важное ограничение (сообщается заранее, не как дефект)

Эта ссылка не подписана криптографически — теоретически кто-то может вручную собрать похожую ссылку с другими значениями. В текущей версии это принятый риск: сама накладная как документ не хранится и не проверяется системой отдельно от QR. Если в будущем понадобится защита от подделки — это можно добавить (подпись ссылки), сообщите администратору приложения, если такая потребность появится.
